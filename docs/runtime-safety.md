# 工具、资料外发与推理资源协调

更新于 2026-11-01。SDK 提供与 Android UI 解耦的策略和协调接口，Companion 0.1.107 实现 Android 集成。
本轮不增加 A2A 文件接收。

## 工具与资源引用

Companion 按每轮开始时的能力快照选择工具：已配置工具、有效授权范围和明确绑定的 A2A 连接。
图片不再根据“保存、上传、远程”等关键词隐藏全部工具；通用任务词也不再替代 A2A 连接选择。
用户明确提到的已配置连接别名仍可绑定目的地；绑定远端时不提供手机 shell。
是否调用工具仍由模型判断，程序负责参数、资源存在性、权限和副作用授权。

`read` 实现 `ToolArgumentPrevalidator`。无效的本轮附件序号、不存在的工作区文件、
不可访问的授权文件和照片在授权弹窗前返回参数错误；执行阶段继续检查实际权限。
这能阻止无效操作，但不能保证小模型不提出错误调用或知识回答一定正确。
原有 `LocalToolRoutingTest` 仍需在实际模型上重新运行，不能用假模型的协议测试替代。

## 模型请求策略

`AgentRuntime` 增加可选 `ModelRequestPolicy`，默认允许，保持宿主按需接入。
策略在实际模型请求前执行，覆盖流式请求、上下文超限重试和通过 runtime 发起的摘要。
`ModelRequest` 带会话 ID、即将发送的消息和 `RESPONSE` / `SUMMARY` 用途。
拒绝时抛出 `ModelRequestRejectedException`，拒绝摘要不会被当成普通摘要失败后继续请求模型。
工具内部的外发检查抛出同一异常时，runtime 结束本轮并将尚未完成的调用记录为授权拒绝，不再让模型重试或改走其他工具。

```kotlin
val runtime = AgentRuntime(
    model = model,
    tools = tools,
    store = store,
    authorizer = toolAuthorizer,
    modelRequestPolicy = ModelRequestPolicy { request ->
        hostDataPolicy.check(request.sessionId, request.purpose, request.messages)
    },
)
```

SDK 不自动识别个人信息，也不猜测 `ModelPort` 是否联网。宿主须绑定实际目的地，
持久保存资料策略，并单独保护绕过 runtime 的模型调用和其他网络出口。
提供给 `compact()` 的自定义摘要函数可能使用不同模型，宿主应按其真实目的地检查。

## Companion 的外发边界

设置 → 工具授权 → 本地资料处理：

- **外发前询问**（默认）：本地资料可能进入在线模型时，确认接收方和资料类别；A2A 在发送任务、表单及附件前独立检查。
- **仅在本机处理**：阻止这些资料进入在线模型或 A2A。它不是整机断网开关；模型发现等不携带会话资料的请求不属于此开关。

工具执行权限和资料外发权限分开；“完全访问权限”不绕过外发检查。
允许一次只批准当前请求；本会话允许覆盖当前接收方及后续资料，切换接收方需重新确认。
外发授权仅保存在当前 Agent 实例，重启、重新配置或关闭会清除；批准后再次检查当前资料处理设置。

来源标签按**整个会话保守继承**，不是逐文件的信息流跟踪：附件、扫描文字、语音转写、工具结果一旦用于会话，
其后生成的回答与摘要仍受相同外发检查约束。来源标签持久保存在应用私有 `local_data_sources` 配置中，
不保存额外的文件内容或人脸特征。旧会话缺少来源信息时按历史资料处理；新建的普通文本会话不因此被标记。
普通直接键入的文字仍由所选模型处理，策略不自动识别其中的隐私信息；需要完全本机对话时应选择本机模型。
扫描和转写文字在填入输入框时即标记来源，修改文字、去掉“扫描原文”标签或生成摘要不会清除策略。
撤销 Android 授权会阻止再次读取原文件，但不会删除已进入历史会话的副本或派生内容，后者继续受外发策略约束。

设置页可查看最近 30 条外发授权记录：时间、接收方、来源类别和允许/拒绝结果。
记录不包含正文、图片、API Key 或 URL 查询参数；记录的是权限决定，不代表网络发送成功。

## 推理协调与生命周期

纯 Kotlin `InferenceCoordinator` 提供取消友好的独占租用和事件回调。
等待中的交互请求优先于批量请求，同级按入队顺序；正在执行的原生算子不强制中断。
租用块必须包含模型创建、推理和安全释放，不能嵌套申请同一个协调器。
诊断回调异常不会破坏资源释放或后续任务。

```kotlin
coordinator.withInference("ocr", InferencePriority.INTERACTIVE) {
    val engine = createEngine()
    try { engine.recognize(input) }
    finally { withContext(NonCancellable) { engine.close() } }
}
```

Companion 在进程内共享同一个协调器，覆盖聊天模型准备和每次推理、摘要、ASR、TTS、
OCR、相册查询/索引、人脸分析/扫描及新增的模型加载验证。
在线聊天请求不占本地推理租用。聊天模型在工具执行期间可以保留权重与会话状态，
不会为了切换辅助推理而未经验证地销毁 KV cache。

流式 ASR 保持采集与模型准备并行：即使模型等待资源，录音可先进入原有最多三秒的有界缓冲；
排队太久或推理跟不上仍会报告缓冲溢出，不静默丢音。
租用覆盖流式识别会话的完整生命周期，关闭完成后才允许下一项推理。
相册语义索引按五张一组释放模型并重新排队，避免一次持有整批一百张。
离开扫描、相册索引、人脸页面会取消相应工作，保留已完成结果。

Android 适配层在获得租用后查询系统低内存状态；处于低内存时拒绝启动该项推理。
`KioraInference` 日志记录操作类别、排队/执行时间和原生堆分配量，不记录用户内容。
这是并发预算与系统低内存保护，**不是固定 MiB 内存上限**；原生堆量不等于 PSS，
映射权重、GPU 和仍驻留的聊天模型必须另行测量。尚不能据此承诺低 RAM 设备不会 OOM。

混合循环使用 Gemma 4 E2B / LiteRT CPU，保持聊天引擎驻留；每轮依次执行聊天回复、
Paraformer 公开样本前三秒、MeloTTS FP32（4 线程，仅合成不播放）、合成文字 OCR、
EmbeddingGemma 2 文字/图片嵌入和无真人图片的人脸模型烟测。辅助模型每次用后关闭。
测试不读取个人相册或注册人员，不验证人脸准确率、相册检索质量或朗读连续性。

- 完整循环耗时 227.7 秒；每轮 10.142～12.004 秒，中位数 11.747 秒。这是六类操作的合计，不是某一模型的延迟。
- 进程 PSS **采样最高** 3,208,078 KiB，约 3.06 GiB，出现在 Embedding 阶段。阶段采样可能漏掉算子内部瞬时峰值。

- 测试实例全部关闭后 PSS 为 335,987 KiB，约 328 MiB；开始时为 145,289 KiB。没有假定它必须回到初始基线，也未把残留内存直接认定为泄漏或缓存。
